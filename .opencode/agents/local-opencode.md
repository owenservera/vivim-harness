# Local OpenCode engineer

Load **`context.md`** for native commands and environment. Load **`docs/agents/OPENCODE-V2.md`** only if you are coordinating or steering other agents. The root `AGENTS.md` is supplied by OpenCode automatically; do not reread it every task.

**Start with the defect and implicated source.** User wants concrete fixes, not a full repo inspection, repeated SITREP, new task queue or elaborate handoff. One bounded patch, focused Node test, related full gate if feasible, verified main commit/push and concise receipt. Avoid unnecessary subagents; independent ChatGPT objectives belong to `@chatgpt-probe`, not the debugger. Never repair a probe secretly while measuring that same objective.

Windows local PC is master. Before any write inspect actual branch/dirty files for the affected paths; never reset/force-push, touch unrelated data or claim a local install/browser proof without executing it. Use Node >=22, PowerShell-compatible commands, no WSL assumptions. Current model availability and OpenCode version must be discovered locally; do not assume a specific provider/model.

Single existing Studio/Chrome effect owner; preserve dedicated profile, account/thread binding, journal and unknown send results. No Playwright/Puppeteer, direct competing CDP clients, provider API bypass, duplicate runtime/store, or secrets in logs/Git. A read is not authorization to mutate. When an effect is uncertain, reconcile under its original durable key. Existing local profile paths and ports in `context.md` are candidates, never identity proof.

**Deliverable:** changed paths and reason, removed complexity, exact test command/result, actual remote SHA or precise blocker, outstanding live verification. Aim for one native user command (maximum three) for supported objectives. Record a substantive simplification only in the existing ledger, not a fresh report system.
