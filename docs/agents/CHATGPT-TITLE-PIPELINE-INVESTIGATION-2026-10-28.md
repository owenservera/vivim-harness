# ChatGPT title pipeline investigation — 2026-10-28

## Finding

The recorded 009/012 commands use `--json` but **not `--include-content`**. The current source deliberately removes every recursively named `text` field at the CLI boundary by default. This exactly reproduces the recorded `displayTitle` shape, `{untrusted, truncated}`, in the synthetic end-to-end test. This is an intentional privacy projection, not a demonstrated serialization defect. The deployed process and raw response were not inspected: whether the live reader actually obtained each title, and whether the running version matched this checkout, remain unconfirmed. `displayTitle: null` means no nonempty cleaned title; the observed object-with-flags is consistent with a nonempty title before projection under this source.

009 reported 18 distinct rendered candidates, no omissions or title truncation, but no visible title text; 012 repeated that observation and lacked an approved target title and sidebar provenance. The investigation group B correctly treated root cause as inconclusive. Neither run proves a duplicate-title pair or establishes a live binding.

## Smallest recommendation and safe reprobe

No product fix is justified for the recorded omission: retain privacy default and use the existing explicit `--include-content` opt-in **only with authorization to expose the returned titles locally**. Documentation or scenario instructions may clarify the flag and privacy implications; do not silently turn on content globally. If an authorized fresh run still lacks a known visible nonempty title with the flag, compare privacy-safe synthetic/approved observations at the DOM-expression result, normalized result, structuredContent and CLI boundary to find the first actual loss before changing code. A title-bearing `textContent` with empty `innerText` is one possible DOM-specific case, not established here.

For 009, arrange two approved disposable visible rendered threads with exactly identical known titles and distinct native `/c/` refs; for 012, establish a specific approved disposable title and a visible sidebar, with verified container selector if sidebar provenance is required. Coordinate with the live-probe owner; do not create, rename, navigate, send, or inspect private content without separate authorization. Request `--include-content` only under explicit content permission, avoid recording unrelated titles, and report incomplete rendered-only coverage, ambiguity and candidate-not-binding status. A missing approved fixture or virtualized link is not evidence of absence.
