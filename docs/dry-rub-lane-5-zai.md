## Agent-context gaps observed

- **Recipe surface vs. `chat` command mismatch:** The AGENTS.md agent-recipe entrypoint directs users to `studio recipe` (families such as `conversation.continue`), but none of the 20 `zai` tasks map to an existing recipe family — the only provider-facing conversation primitive is `studio chat <site> --prompt`. Recipes exist for orchestration, not for arbitrary LLM prompts, so there is no recipe-capable path for these generic chat scenarios.
- **No `zai`-specific recipe family:** `studio recipe list` shows families; `zai` is only reachable as a `chat` site, not as a recipe target. Agent-context discovery (`studio agent capabilities`) reports recipe count and families statically, with `browserAccountState: 'unknown-not-probed'`, so it cannot confirm whether `zai` is a live, credentialed provider.
- **Dry-run is a static preview only:** The dry-run path (chat.mjs:19-22) emits `connect-submit-poll-finish` with `browserAction: false` without constructing the runtime or performing target discovery. It validates the prompt shape and flags but never reaches the provider, so it cannot surface provider-specific capability gaps (e.g., whether `zai` honors "exactly this text and nothing else" constraints).
- **Fixed default timeout:** `timeoutSeconds` is always 120 in dry-run regardless of task complexity; there is no per-task or per-prompt timeout hint exposed to the agent.
- **No live confirmation:** All 20 tasks are dry-runs (zero effect). No browser was launched and no provider send occurred, so live `zai` acceptance, credential state, and actual output fidelity remain unverified.
