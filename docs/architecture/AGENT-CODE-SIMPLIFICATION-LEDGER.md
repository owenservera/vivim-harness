## Target shape after consolidation

1. User/agent chooses an **outcome** with `studio recipe choose` or a known ID.
2. `studio recipe plan` checks typed eligibility and authorization without effect.
3. `studio recipe run` binds a durable operation to the single existing runtime owner.
4. Native tools decide actual browser/capture effects and persist exact turn/capture evidence.
5. `studio recipe status/reconcile` return the **original** run and the smallest safe next action, never a replacement send.

A good pass **reduces** the number of concepts: command registry, native tool manifest, harness run journal, browser owner and recipe catalogue remain separate only because they serve different proven duties. No second auth system, scheduler, generic script engine, browser actor or storage authority.
